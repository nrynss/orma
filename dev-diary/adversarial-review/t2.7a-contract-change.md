# T2.7a contract change

T2.7a owns `_shared/finalise.ts` and `tick/index.ts`. Every change below sits
inside those two paths or records a decision the reviewer should see. Nothing
outside the `owns` line was reached.

| Where | What | Pin | Mutation |
| --- | --- | --- | --- |
| `tick/index.ts` `TerminalTickRun`, `TickDeps.finalise`, `terminalRuns` | Widen the terminal-run shape with `user_id` and `calle_call_id`, and read both in the terminal select. Ingestion needs the owner, and the re-fetch needs the provider id. | The in-file tick check `a failed re-fetch leaves its run queued while its siblings finalise` drives the real `depsFromEnv` and asserts the ingest request carries the run's own identity while the stuck sibling never reaches ingestion. The stack driver reads `completed_at` back in SQL. | Reading the run a second time inside `finalise.ts` would cost one extra query per run and would hand ingestion an owner that no selector verified. |
| `tick/index.ts` `depsFromEnv` | Replace `unavailable("finalisation")` with the real finaliser, and delete the now unused `unavailable` helper. | `deno test --allow-env --allow-read --allow-net supabase/functions/tick/index.ts` reaches `ingest_call_result` through `depsFromEnv`, which the stub never did. | Restoring the stub leaves every terminal run queued forever, because only ingestion writes `completed_at`. |
| `_shared/finalise.ts` `failureReason` | The `finalised` row names the provider's `failure_code`, never its `failure_message`. | The in-file check `a failed call names the provider's code and not its free text` feeds the recorded failed message and asserts the row does not contain it. | Pasting the message puts provider free text into an operator-readable row, which the `call_events` contract forbids for numbers. ## One consequence to judge

A terminal run with no `calle_call_id` never leaves the finaliser queue. Only
`poll.ts`'s defensive branch writes that pair of conditions, when a run reaches
`dispatched` with no stored provider id. The run keeps a truthful `failed` state
and its `poll_unavailable` failure, and it costs one failed check per tick with
no outbound request. The alternative was to exclude such a run from the terminal
select, which would change the selector the task specifies and leave the run
looking unfinished.

## One discrepancy in the briefing

The task text says `_shared/calle.ts` exports `fetchCall`. It does not. T2.5
exports `fetchCall` and `terminalStateFor` from `_shared/poll.ts`, and the
finaliser imports both from there. `calle.ts` exports `depsFromEnv`, which is
the CALL-E transport the finaliser takes.
