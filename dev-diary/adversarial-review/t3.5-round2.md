## Independent checks

`deno` was not on PATH. Deno 2.9.6 was installed only for this review.

`deno test --allow-read supabase/functions/telegram/link.ts` reported 11 passed, 0 failed.

A fresh mint then `completeLink` on the memory store set `profiles.telegram_chat_id` to the start chat. The store had no row keyed by the raw token.

A second `completeLink` with the same token returned `replay`. The original chat id stayed on the profile. The second chat id did not resolve.

`completeLink` at `now + LINK_TOKEN_TTL_MS` returned `expired`. `telegramChatId` stayed null. `consumedAt` stayed null.

`completeLink` at `now + LINK_TOKEN_TTL_MS + 1` also returned `expired`.

`tokenFromStartText("/start")` returned null. `completeLink` then returned `missing`. `messageForLinkOutcome` equalled `START_LINK_PROMPT`.

`encodeLinkToken` of 32 random bytes produced a 43-character payload. `hashLinkToken` produced 64 lowercase hex characters. `telegramStartDeepLink("@orma_tele_bot", token)` equalled `https://t.me/orma_tele_bot?start=` plus that token.

The REST mint double posted `token_hash` to `https://orma-api.nryn.dev/rest/v1/telegram_link_tokens`. The body did not contain the raw token. The URL did not contain `supabase.co`.

An independent REST double for `completeLink` sent PATCH with `consumed_at=is.null` on that same host.

A delayed REST double under `Promise.all` of two `mintLinkToken` calls serialized delete then insert. The mock held one live row.

`test -f supabase/migrations/*telegram_link*` exited 1. Generated types have no `telegram_link_tokens` table.

Remediation introduced no new defect inside the T3.5 seam that this review records as a finding.

## Accepted for this round

The contract note is still honest. T3.5 cannot add `telegram_link_tokens`, wire T3.1 `/start`, or mint from Settings.

Done-when bind, replay, expiry, and unlink still hold on the memory store. They are not met on a live Start press until T3.1 calls `completeLink`.

A taken chat still consumes the token. Spec says a token is consumed on first use.

If `unmarkTokenConsumed` also throws after a failed bind, `consumedAt` stays set. That nested rollback miss is not the round one H pin.

`replaceOpenTokenForUser` on the REST adapter is still two round trips. `mintLinkToken` serializes those calls in one isolate.

`profiles` RLS still lets an owner PATCH `telegram_chat_id` without a token. T1.2 owns that policy.

Tests live in `link.ts` because that is the T3.5 `owns` seam.

T3.5 status remains `claimed:orma`. This review does not mark the task done.
