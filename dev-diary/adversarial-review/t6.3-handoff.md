# T6.3 handoff: History

Implementation role. This work is ready for independent review.

## What exists now

`/app/history` is a browser-rendered owner view under RLS. It reads the signed-in
profile zone, that owner's non-scheduled and non-canceled runs newest first, and the
transcripts, results, items, mentions, and commitments for those runs. It never edits
anything under `web/src/lib` and adds no check scripts.

- Newest call renders expanded with day label, clock, duration, disposition, count
  tags, summary lines, and turns in offset order. Earlier calls render as collapsed
  rows under Earlier. Mood renders through the shared MoodMarker and is never editable.
- Per-run retired, committed, captured, and mention counts reuse lastCallSummary, so
  Today and History agree by construction. Offsets format through formatOffset. Every
  clock renders through formatClock and formatDayLabel in the profile timezone.
- Transcript speakers map agent and bot to Orma and user and callee to You. Offsets
  link to `?run=<id>&t=<seconds>`. Retirement and commitment evidence offsets link the
  same way. The `run` param selects the expanded call and the `t` param highlights and
  scrolls to the turn at that offset.
- A run with no results row, or with `valid` false, still renders its transcript with
  the honest line that Orma wrote nothing down. Internals never surface.
- Not-answered and failed runs show the design line that the call did not connect.
  Live runs show an on-the-call header with no summary yet.
- Read failure renders the error state, like the items page. An account with no calls
  shows an anticipation line rather than blank panels.
