## Residue I did not close

* **A persistent refusal of the call_events endpoint** still loses the `finalised` row, because the
  retry covers a transient failure only. The run keeps its `ingested` row and its `completed_at`,
  and its run row now names the loss. A cross-tick retry would need the run back in a queue that
  the new selection no longer owns.
* **The finaliser still records no `refetched` row.** Round 1 left that judgement to T2.9, and I did
  not move it.
* **Two ticks that fail the same attempt together count two attempts.** The boundary locks the run
  row, so the count is exact and ordered. Both ticks still spend an attempt from one outage.
