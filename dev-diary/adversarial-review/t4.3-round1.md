# T4.3 round 1: adversarial review of docs/mcp.md

**Verdict: REMEDIATE.**

Counts: C 0, H 1, M 3, L 2. Six findings. Each pin below is a measurement I ran
today against the live endpoint, the working tree, or the source, never a quote
of the implementation report.

## What I measured

- Connect. I substituted only the token. Initialize returned HTTP 200 with
  `protocolVersion 2025-03-26` and `serverInfo orma 0.1.0`. The initialized
  notification returned 202. tools/list returned HTTP 200 and named exactly
  `add_item`, `list_items`, `retire_item`, `set_slot`, `get_last_call` and
  `get_patterns`. No `apikey` header was sent. The done-when connect holds.
- Tool names. `TOOL_NAMES` in `supabase/functions/mcp/tools/types.ts` matches
  the doc's six names in the same order.
- Worked examples. All six reproduce their documented shapes key for key.
  add_item returns the ten documented item fields with `source "mcp"`.
  list_items returns an array of the same shape and drops retired items.
  retire_item returns the row plus `retired_by`, `retired_surface "mcp"` and
  `reversible true`, with `retired_reason` of `mcp:<user id>:<note>`.
  set_slot stores `08:30` as `"08:30:00"` and defaults weekdays to 1 to 7 and
  active to true. get_last_call and get_patterns return `null` on a fresh
  account. `reason` stays optional and `slot_id` updates in place.
- Failure shapes. A missing token and a malformed token both return HTTP 401
  with code `-32001` and the exact documented messages. A wrong-user retire
  returns the documented tool error. An already-retired item and a nonexistent
  id return that same message.
- Prose claims that measured true. The grant answers `expires_in` 3600. An
  unconfirmed grant is refused with `Email not confirmed`. Without a profile
  row, add_item fails on `items_user_id_fkey`. A restore under the caller
  token clears status and the retired fields and the item re-enters
  list_items.
- Prose claims that measured false. See H1, M1 and L1 below.
- Hygiene. No token, key, or phone-shaped string sits in the doc. Three
  UUID-shaped strings match no live row: zero rows in items, slots and
  profiles, and auth admin reads answer 404 for all three. They appear nowhere
  else in the repo.
- Style. No semicolons and no em dashes. No sentence runs past 30 words. Two
  passive sentences lack a clarity gain and are filed as L2.
- Cleanup. I deleted every probe row and user I created, then verified the
  deletion. Counts read 0 for both probe user ids across items, slots and
  profiles. Auth admin reads of all three probe users answer 404.
