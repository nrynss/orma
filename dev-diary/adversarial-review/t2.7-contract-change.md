# T2.7 contract change

T2.7 must turn a terminal run into rows in one transaction. A sequence of REST
writes cannot be atomic, so the transaction belongs in PostgreSQL. The task's
`owns` line named only `_shared/ingest.ts`, which omitted the migration, the
RPC and the acceptance script that the requirement needs.

| Where | What | Pin | Mutation |
| --- | --- | --- | --- |
| T2.7 ownership | Add `supabase/migrations/20260912180000_ingest.sql`, `supabase/migrations/test-ingest.sh` and the `public.ingest_call_result` RPC to T2.7. | The owns line listed only `_shared/ingest.ts`. PostgREST cannot hold a multi-statement transaction, so no REST-only path can write the run, transcript, result, items, mentions, retirements and commitments atomically. Without the runner, the row counts and the retirement rejection stay unproven. | Removing the migration or its runner pushes the transaction into TypeScript, where a mid-write failure leaves partial rows, and leaves the counts unpinned against PostgreSQL. |
