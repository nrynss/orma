# T5.3 contract change

The original `owns` line named the client module, `+layout.ts`, and `login/`.
Cookie sessions, the Settings JWT wiring, and the secret-key build check sit
outside that list, and the task text already requires all three.

| Where | What | Pin | Mutation |
|---|---|---|---|
| `web/src/hooks.server.ts` | Read and write the auth cookies on every request so a reload keeps the session. | A signed-in reload of an app route still has a session. | Without the hook, server loads see no cookies and bounce a valid user to login. |
| `web/src/routes/+layout.svelte` | The file already exists. The load in `+layout.ts` has to reach the tree. | App routes render from the load session rather than a pasted token. | Leaving the layout untouched leaves Settings on the T3 paste form. |
| `web/src/routes/app/settings/+page.svelte` | Call `getSession()` (or the exported helper) and pass `access_token` plus `user.id` into the existing mint and unlink helpers. | Settings mint inserts one `telegram_link_tokens` row for that user. | The paste form survives, which fails the T5.3 done-when pin. |
| `web/package.json`, `web/package-lock.json` | Add the publishable Supabase client. Add a build check that fails if a secret key appears under `web/`. | `npm run check` fails when `SUPABASE_SECRET_KEY` or `sb_secret` is present under `web/`. | The secret key can ship in the Worker bundle, which AGENTS.md forbids. |
| `web/src/routes/+layout.server.ts` | Pass the hook session into the tree. `+layout.ts` stays the universal load and does not import `$app/server`. | A signed-in SSR of Settings has `data.session`. The client layout node does not call `getRequestEvent`. | A server-only import in `+layout.ts` ships `getRequestEvent` into the browser bundle, and client navigations throw. |
| `web/scripts/` | `with-public-env.mjs` maps `ORMA_API_URL` and `SUPABASE_ANON_KEY` onto SvelteKit PUBLIC_ names at build. `check-no-secret-key.mjs` fails `npm run check` if a secret key appears under `web/`. | `package.json` `check` and `build` invoke both scripts. A planted `SUPABASE_SECRET_KEY` in web source fails check. | Without the mapper the Worker inlines empty PUBLIC_ values and auth 500s. Without the scanner a secret key can ship in the bundle. |
| `web/src/lib/telegram-link.ts` | Round 1 F1. `headers()` sent the user JWT as `apikey`. Live PostgREST through the front door returns 401 Invalid API key, so Settings mint inserts no row. Send the publishable anon key as `apikey` and the user JWT as Bearer only. | Helper-shaped POST with JWT as both headers returned 401 and count 0. Anon `apikey` plus user Bearer returned 201 and count 1. | Restore JWT-as-apikey and Settings mint 401s. The Start link never appears. |

The operator confirmed the scripts row and the helper row. A task that needs a
file owns that file through a contract change. It is not an owns excursion.
