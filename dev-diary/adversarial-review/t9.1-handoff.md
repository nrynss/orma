## What did not change

No page file, no loader, no `model.ts`, no `+page.ts`, no layout, no `web/package.json`,
no query, no status line. This task writes `web/src/app.html`, `web/src/lib/ui/` and
`web/src/routes/dev/ui/` and nothing else. The tree also carries the P9 claim edits to
`dev-diary/PHASE-9-ui.md` and `dev-diary/README.md`, and the operator's
`dev-diary/adversarial-review/p9-contract-change.md`. Neither came from this task, and a
reviewer can separate them from the diff of these three paths.

The retired editorial names are gone with no aliases, as the P9 contract change
requires: `--o-paper`, `--o-ink`, `--o-muted`, `--o-rule`, `--o-hair`, `--o-line`,
`--o-plum`, `--o-wash`, `--o-danger`, `--o-on-accent`, `--o-serif` and `--o-mono`.
The global helper classes that carried them went too: `.o-app`, `.o-h1`, `.o-h2`,
`.o-hint`, `.o-gloss`, `.o-label`, `.o-mono`, `.o-muted`, `.o-stack`, `.o-row`,
`.o-wash`, the four `.o-btn` classes, `.o-tag` and `.o-link-button`. Each page moves
its own markup on its own task, and the base layer keeps every page legible until then.
The pre-existing convention stands: every class this system authors carries an `o-`
prefix, so a shared rule never meets a page rule.

### Why `app.html` changed

`app.html` gained one line: `<meta name="color-scheme" content="light dark" />`. The
token sheet states the same thing on `:root`, but that statement arrives with the
stylesheet. The meta tag states it in the document head, so the browser paints native
form controls, the scrollbar and the overscroll edge in the reader's own scheme from
the first frame. Without it a dark mode phone shows a light native control and a white
overscroll edge while the stylesheet loads, and the demo films that phone. Nothing else
in `app.html` moved.

## Tokens

Every colour role is declared once, as `light-dark(light, dark)`, against a fixed
palette. One declaration therefore serves both themes. A `[data-theme]` wrapper sets
`color-scheme` on a subtree, and every role inside it flips. The gallery uses that
for its two panes.

The role tokens carry no prefix on purpose. `--o-*` was the editorial set, so the
product set takes plain role names, and after T9.8 the tree holds no `var(--o-` reading.
Classes keep the `o-` prefix, which is the convention that keeps a shared rule away from
a page rule.

Three notes for the page tasks.

`Button` renders an `<a>` when it receives `href`, and a `<button>` otherwise. Every
button keeps a 44 pixel minimum height, so no variant can shrink a touch target.
`ariaPressed` applies to the button branch only, because a link cannot be pressed.

`Field` renders a `<label>`, so the control inside associates with no id to keep in
step. It also styles `input`, `select` and `textarea` descendants, checks and radios
apart, which is how the system stays out of the page style blocks while preventing
two pages from drawing one field two ways.

`AppNav`, `MoodMarker`, `ItemLine` and `LiveDot` keep their export names and their
props. Only their styles changed, so every page that imports them still compiles.

## The gallery and the production guard

The gallery lives at `/dev/ui`. It renders every colour role, the type scale, the
space scale, the radii, the elevations, the motion tokens and every component in
every variant, in a light pane and a dark pane side by side.

`web/src/routes/dev/ui/+page.ts` is the whole guard:

```ts
import { dev } from '$app/environment'
import { error } from '@sveltejs/kit'
import type { PageLoad } from './$types'

export const load: PageLoad = () => {
	if (!dev) error(404, 'Not found')
	return {}
}
```

That refusal is measured, not hoped for. Three reads settle it.

1. `dev` is a build constant. `@sveltejs/kit/src/exports/vite/index.js:431` defines
   `__SVELTEKIT_DEV__` as `s(!is_build)`, and line 300 sets
   `is_build = config_env.command === 'build'`. `npm run build` and `npm run preview`
   therefore carry `dev === false` in the server bundle and in the client bundle.
2. `error(404, ...)` throws an `HttpError` with `status` 404
   (`@sveltejs/kit/src/exports/internal/index.js`).
3. A thrown load error reaches `get_status(err)`, which returns that status, and
   `render_response` is called with it
   (`@sveltejs/kit/src/runtime/server/page/index.js:284` and `:316`). With no
   `+error.svelte` in the tree, the fallback is `static_error_page` with the same
   status at `:334`.

So a production response for `/dev/ui` is a 404, from the server and from a client
side navigation alike, because both bundles read the same false constant. The route
is not prerendered, since the root `+layout.server.ts` sets `prerender = false`.

The page chunk is still built into the production bundle, because removing a route at
build time belongs in `vite.config.ts`, which this task does not own. The requirement
is the 404, and the 404 holds.

The gallery imports `$lib/ui/tokens.css` itself. The app layout is still the only
other importer until T9.2 lifts the import to the root layout.
