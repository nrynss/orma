## The overlap with `_shared/finalise.ts`, closed

Before this round, `_shared/finalise.ts` retried the same append through its own
`appendTimelineRow`, three times, so the two budgets nested and a permanently
failing `finalised` append made nine requests instead of three. Its in-file
check `a lost finalised append never becomes a second ingest` reported
`saw 9`.

The orchestrator widened the `owns` line to `_shared/finalise.ts`, and the
wrapper's retry loop is gone. One budget now serves every caller. The run-row
loss record stays, because that is the part the helper cannot do: a spent
append still travels through `recordAttempt` as the attempt's reason, so
`call_runs.finalise_error` names the loss and the operator still learns a row
was lost.

Observed, `/tmp/t29/finaliser-count.ts`, a stub that fails every append:

```text
pass 1: /call_events requests 3, outcome call event insert failed
pass 2: /call_events requests 3, outcome call event insert failed
pass 3: /call_events requests 3, outcome resolved
```

Three requests per pass, and the attempt budget still ends the run on the third
pass. The behaviour is bounded, at about 0.5 seconds of pause per pass and well
inside the 150 second wall clock an Edge Function allows.
