## The wordmark, and the one clause I did not follow literally

`Wordmark.svelte` renders both files and CSS picks one. The light file shows by
default, the dark file shows under `@media (prefers-color-scheme: dark)`, and a
`[data-theme]` ancestor wins over that media query in both directions. That is the
same pair of mechanisms the tokens use, so a subtree that flips `color-scheme` flips
the artwork with it.

Both images carry `alt="Orma"`. The brief asks for `aria-hidden="true"` and an empty
alt on the hidden one instead. I did not write that, and here is why.

CSS decides which image is visible, and CSS cannot set an attribute. A static
`aria-hidden` pair is wrong in one theme by construction. Give the dark image
`aria-hidden="true"` and an empty alt, and the link loses its name the moment the
reader is in dark mode. The link is then unnamed until hydration, and unnamed without
JavaScript for good.

`display: none` already takes the hidden image out of the accessibility tree, the tab
order and the layout. So exactly one image is ever exposed, and its alt names the link
once. The pin is in the measurements below. The reviewer should check the reasoning
rather than take it from me, and should say so if they want the attribute pair instead.

## Reviewer focus

1. **The wordmark switch.** Read `Wordmark.svelte` against the measurements above.
   Check the six `[data-theme]` rows, the source of each rendered image, and the
   natural size. Then judge the alt decision in the section above on its merits. If
   you want the static `aria-hidden` and empty alt the brief names, say so, because
   that choice trades a theme-correct name for a literal one.
2. **The 44 pixel targets.** Re-measure every target in the table. The old shell bar
   measured 25.6, so a regression here is the defect this task exists to remove.
   Include the tab links, the public header links, the account trigger and the desk
   nav links.
3. **The tab bar clearance.** Scroll each app page to the document bottom and compare
   the last content edge with the tab bar's top. The frame adds 56 pixels, the safe
   area inset and 24 pixels of gap. Check the six pages, not one.
4. **One navigation per page.** Count rendered nav boxes, not `nav` elements. Two
   exist in the markup by design, so check the crossover at 899 and 900 wide and
   every other width in the table.

1. **`/app/patterns` scrolls sideways at 360.** The page's own mood trend holds a

   is T9.7's and the design canvas draws the same width. Nothing in the shell causes
   it, and no other page does it.
2. **The desk pages still centre a 38rem column.** The frame leaves page width and
   gutters alone, because every page sets its own padding today. The wide desk content
   area in the phase text belongs to T9.5 to T9.8, which own those style blocks.
3. **The landing and the login page still print Orma as text.** Their `h1` elements
   carry the word, and their style blocks still hold literal colours that beat the
   tokens. T9.3 owns both files. Within T9.2's paths no visible Orma text is left.
4. **The viewport meta now carries `viewport-fit=cover`.** The orchestrator widened
   this task's owns for that one line in `web/src/app.html`. Without it
   `env(safe-area-inset-bottom)` resolves to 0, so the tab bar would sit on the home
   indicator on iOS. The rendered meta is measured below.
5. **The operator's phone walk stays owed.** Contract change row 5 records it. I ran
   no phone and I claim none.
6. **The account menu closes on navigation and on Escape.** It does not close on an
   outside click. That is a deliberate minimum, and a reviewer may ask for more.
7. **Page content links stay short.** The frame's own targets clear 44. The links a
   page draws inside its prose measured 20 to 22 pixels on `/app` today. T9.5 to T9.8
