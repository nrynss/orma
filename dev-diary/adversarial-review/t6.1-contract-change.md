# T6.1 contract change

The original `owns` line named only `web/src/routes/app/+page.svelte`. The P5 handoffs left three gaps that sit outside every P6 owns line. This task takes them, because every later page builds on them. The operator recorded these rows at the claim.

| Where | What | Pin | Mutation |
|---|---|---|---|
| `web/src/routes/app/+page.ts` | Today reads its data in the browser. Spec §11 marks `/app` as client rendered. | A signed-in `/app` renders the next run, open items and the last call for the seed account. | Without a load, the page has nothing to render and `/app` stays a 404. |
| `web/src/routes/app/+layout.svelte` | The app navigation from the design: Today, Items, History, Patterns, Timeline, Settings, the display name, and Sign out. | Every signed-in `/app/*` page shows the navigation, and the current page is marked. | Each later page would build its own navigation, or none. |
| `web/src/routes/+layout.svelte` | The root shell bar holds Settings and Sign out today. Inside `/app` it must not duplicate the app navigation. Signed out, it keeps Sign in. | `/app` shows one navigation. `/login` still shows no Sign in link. | Two navigation bars on every app page. |
| `web/src/lib/ui/` | Shared tokens and small components from `design/orma-app/System.dc.html`, in light and dark. | Today uses them. A later page can import them without copying styles. | Six pages copy the same tokens and drift apart. |
| `web/src/lib/today/` | Pure helpers for Today, such as next run selection and time in the profile's zone, with a check script. | The check fails if the next run renders in the browser's zone instead of the profile's. | A timezone regression ships with no failing check. |
| `web/src/routes/app/onboarding/profile-gate.ts` and `check.ts` | `postAuthPath` returns `/app` for a finished profile instead of `/app/settings`. | Login with a finished profile lands on `/app`. The onboarding check asserts the new path. | Users keep landing on Settings, and Today is never the first screen. |
| `web/src/routes/app/onboarding/+page.svelte` | After submit, go to `/app` rather than `/app/settings`. | A completed onboarding lands on Today in its first-run state. | The first-run state is never seen by the person it was designed for. |
| `web/package.json` | Wire the Today check into `npm run check`. | `npm run check` runs the Today assertions. | The check file exists and never runs. |
| `scripts/p6-local-stack.sh` | A bounded scratch Supabase stack with every migration and `supabase/seed.sql`, plus harness-only rows such as a future scheduled run. It prints the local API URL for `npm run dev`. | The script brings up a stack the seed account can sign into. It never touches the linked project. | Every P6 reviewer probes production, which has no calls, or rebuilds a harness from scratch. |

Do not edit `supabase/seed.sql`. T1.6 owns it. Harness-only rows stay in the script and in the scratch database. Do not add a cancel control that writes `call_runs`. That table is read-only to its owner, and T6.7 adds the function T6.5 uses.
