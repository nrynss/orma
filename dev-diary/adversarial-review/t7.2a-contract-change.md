# T7.2a contract change

T7.2a owns `supabase/functions/_shared/vertex.ts` and
`supabase/functions/_shared/vertex_tests.ts`. The shared module holds the
service-account credential path and the Vertex URL convention.

Round 1 review found a second exported `vertexGenerateContentUrl`
implementation in `supabase/functions/telegram/voice.ts` at lines 113 to
122. Two exported URL builders are the seed of a second Vertex
convention. Any caller could import the URL from telegram with no tie to
the credential path the shared module owns.

## Authorized change

The orchestrator authorized a one-line edit to
`supabase/functions/telegram/voice.ts` for this remediation round only.
The duplicate implementation is replaced by a re-export of the shared
implementation from `../_shared/vertex.ts`. The exported name and call
signature stay the same. Existing voice tests keep importing the name
from `telegram/voice.ts` and pass unchanged.

## Why authorized

Consolidation is the point of the shared module. Leaving a public second
copy would keep the second convention alive inside the telegram seam.

## Residual

None. `telegram/voice.ts` holds no URL or credential logic after this
change.
