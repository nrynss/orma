## Residual risk

**A claim whose dispatch never starts is stranded the same way.** N1 measures the timeline
insert as the trigger. An invocation that dies between the committed claim and the first
dispatch step strands every claimed run of that batch. The 150 second wall clock is one way
to die there. No lease and no expiry repairs it.

**A failed dry ingestion leaves a run for the finaliser with a synthetic call id.** S4(d)
leaves the run terminal, with a null `completed_at`, and out of the poll's reach because
`poll_after` is null. `terminalRuns` selects it. Its `calle_call_id` reads
`fixture:call_tQA8nz1WGj9vfO30PxTosA`, so T2.7a must not re-fetch it against CALL-E.

**T2.7a inherits the masking rule.** The dry path stores a mask. A live completion will store
the provider payload through the same ingestion seam. That payload carries the callee's
number in `recipients[].phones[]` and inside `transcripts.raw`, which the run owner may read.

**Nothing sets `call_runs.dry_run` in production.** The column is an operator override and it
needs an `UPDATE` today. A run dispatched dry under the global default still reads
`dry_run` false, so the column never answers "did this run really call".

**The local seed writes a terminal row with no writer tag.** `supabase/seed.sql:99-130`
inserts a `completed` run with `terminal_writer` null, so a null tag does not always mean a
refusal. That row predates T2.8 and the comment's null sentence covers it by omission.

**If the fixture choice is ever exposed, a `canceled` fixture would fail.** The finalised
event asserts a failure reason for any state matching `cancel`. The dry writer passes an
empty string, so a canceled fixture would throw after ingestion. Today no fixture reaches it.

**Seven leading characters of a number survive the mask.** That matches the convention the
dev-diary samples already use, so I raise no finding. I record it here because the run owner
can read it.
