## The whole briefing, checked for a value a model can influence

Every substitution was read again after the H fix.

* `user_name` is `profiles.display_name`, which the user set. No model writes it.
* `open_count` is a SQL count and is never templated into a sentence.
* `slot_local_time` is `slots.local_time`, which the user or an operator set.
* `lead_line` renders SQL counts of `item_mentions` and an age from `since_date`.
* `open_items` lists the item text beside the item id.
* `last_call_summary` is now the row-derived sentence this round introduced.

One channel remains, and it is unchanged on purpose. `items.text` is the prose
the extraction captured, so a captured item that says `3 tickets` carries a
digit. That text reaches `open_items`, and the lead line speaks it beside a SQL
count. Two reasons leave it alone. The user said those words, and the row keeps
the evidence offset of the turn. The task also forbids capturing an item the
user did not confirm in their next reply. The round one review recorded the same
channel in its section 3. Blocking digits there would refuse a real item such as
`buy 3 tickets`. `transcripts` is no longer read by the briefing at all, so the
raw call text reaches nothing.
