# T3.1 contract change request

T3.1 owns only `supabase/functions/telegram/index.ts`. JWT-off for this
function still lives in `supabase/config.toml`, which T5.1 owns.

The handler reads `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, and
`ORMA_API_URL` from the function environment at runtime. Those names match
GitHub secrets and `scripts/bootstrap-env.sh`. This task does not commit values.

Boot and GET register `setWebhook` using `ORMA_API_URL`. They never use a
`*.supabase.co` host.

| Where | What | Pin | Mutation |
| --- | --- | --- | --- |
| `supabase/config.toml`, owned by T5.1 | Telegram posts webhooks with no JWT. A CLI deploy that still verifies JWTs never reaches the path-secret check. | A gateway 401 JSON body on `POST /functions/v1/telegram` with no Authorization header, instead of this function's empty 401. | `@orma_tele_bot` cannot deliver updates. Live secret rejection cannot be pinned. |
