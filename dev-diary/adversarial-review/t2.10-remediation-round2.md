## The give-up paths, read end to end

Five writers can end a run, and each writes its disposition where it ends it.

| Writer | State | Disposition | Billed |
| --- | --- | --- | --- |
| `ingest_call_result` | from the payload | from the payload | the disposition, and a real call id |
| `abandon_call_run` | whatever the run held, `failed` in practice | `not_answered` | never |
| the poll's give-up | `failed` | `not_answered` | never |
| the dispatch refusal | `canceled` | `canceled` | never |
| the dispatch recovery | `failed` | `not_answered` | never |

The refusal and the recovery live in `_shared/calle.ts`, which this task does not
own. Both already write their disposition, and both leave `billable` at its
default false, which is the value their disposition requires. Nothing can set
`billable` true before a terminal write, because ingestion is the only writer
that does and it is terminal itself. The finding was the finaliser's give-up
alone, and it is closed.
