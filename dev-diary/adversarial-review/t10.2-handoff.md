# T10.2 handoff: Confirmation call and code check

## What landed

`confirm-phone` creates an expiring, rate-limited confirmation request and dispatches a single code call through the shared CALL-E client. `verify_phone_code` confirms only the caller's current number.

Confirmation webhooks update only confirmation state. They cannot write a `call_runs` row. Recovery links a provider call only from unexpired recoverable states.

## Safety controls

- The database stores a salted code hash, never the code.
- Dry-run responses return the code only outside production.
- Dry-run audit data masks the phone number, webhook secret, and code.
- Changing a phone number expires pending or failed confirmations.
- Expired confirmations cannot become dialled after a delayed webhook.

## Validation and review

Round 4 approved with zero findings. It independently checked all earlier mutations, including stale A to B to A confirmation, masking, lost dispatch persistence, and delayed completed webhooks.

The Deno checks and 90 focused tests passed. No live CALL-E call was placed.
