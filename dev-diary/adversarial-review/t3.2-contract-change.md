# T3.2 contract change request

T3.2 owns only `supabase/functions/telegram/capture.ts`. Plain-message
insert, the quoted recorded reply, and the unlinked prompt live there.

The webhook that receives Telegram updates lives in T3.1 `index.ts`.
This task does not edit that file.

`createRestCaptureStore` reads profiles and inserts items through
`ORMA_API_URL` with `SUPABASE_SERVICE_ROLE_KEY`. T3.1 `depsFromEnv`
does not yet load that key.

| Where | What | Pin | Mutation |
| --- | --- | --- | --- |
| `supabase/functions/telegram/index.ts`, owned by T3.1 | A non-command text update must call `captureTextMessage` and reply with its `reply`. Skip `/start`, which T3.5 already claims. | POST a text update from a chat whose `profiles.telegram_chat_id` matches. One new `items` row has that `user_id` and `source = telegram`. The Bot API JSON `text` equals `recordedCaptureReply` of the stored text. A POST from an unknown chat sends `START_LINK_PROMPT` and inserts zero rows. | Capture helpers exist, but a live message never inserts and never replies. An unlinked chat stays silent. |
| T3.1 `TelegramDeps` / `depsFromEnv` | Runtime must also require `SUPABASE_SERVICE_ROLE_KEY` so `createRestCaptureStore` can run. | `depsFromEnv` with that name unset throws `missing SUPABASE_SERVICE_ROLE_KEY`. Rest inserts use `ORMA_API_URL`, never a project host. | The handler can parse an update and still cannot write `items`. |
