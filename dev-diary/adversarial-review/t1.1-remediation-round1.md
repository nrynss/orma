# T1.1 remediation round 1

## Scope

This remediation addresses H1 from `t1.1-round1.md`. It adds a self-contained,
local-only migration acceptance runner at
`supabase/migrations/test-core-schema.sh`.

| Finding | Remediation | Validation | Mutation covered |
| --- | --- | --- | --- |
| H1 | The runner creates an isolated temporary Supabase project, copies the core migration, starts the local stack, and runs `supabase db reset --local`. It inserts an invalid E.164 phone and a duplicate idempotency key inside exception assertions. It seeds selective tick data, captures `EXPLAIN`, and fails unless PostgreSQL reports `Index Scan using call_runs_state_scheduled_for_idx`. The exit trap stops the temporary stack. | `bash -n supabase/migrations/test-core-schema.sh` passed. An isolated local reset applied `20260911000000_core_schema.sql` cleanly. The acceptance SQL completed both expected-rejection assertions and returned `Index Scan using call_runs_state_scheduled_for_idx on call_runs` with the tick predicate. All probe rows rolled back. | Removing the phone check, unique key, or tick index makes the runner fail. A migration that no longer resets cleanly also makes the runner fail before probes run. |

## Local-only boundary

The runner has no project link and performs no remote or live-project writes.
It does not place a CALL-E request.
