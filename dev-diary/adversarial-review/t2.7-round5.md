## Fix 1, the general phone pattern

`/tmp/t27r5/probe-local.ts` drives the real module with a mock PostgREST body whose message embeds
one candidate spelling. The thrown cause is the measurement. 52 spellings give 4 leaks, 40 masks
and 8 untouched rows. The four leaks all come through the same lift:

| --- | --- | --- |
| `####-##-####` | LEAK | whole number in the cause |
| `####-##-##-##` | LEAK | whole number in the cause |
| `####-##-####-####-##-####` | LEAK | whole number in the cause |
| `+####-##-####` | LEAK | whole number in the cause |
| `#### ## ####` (space 4-2-4, the shipped test's own spelling) | masked | control |
| `###-###-####`, both comma spellings, en dash, em dash, zero width space, soft hyphen, both apostrophes, backslash, colon space, middle dot, fullwidth digits, fullwidth plus, Arabic-Indic digits | masked | each one masks whole |

  contradictory payload.

* `spec.md:216` lists `no_result` in the terminal state set. Nothing writes it. The webhook maps the
  re-fetched status, and the RPC accepts three states, so a validation failed run lands as
  `completed` with `answered_no_result`, which is the disposition the spec's table asks for. The only
  reader of `no_result` is the finaliser's queue filter, which reads it defensively.
* `p_skipped` is accepted as any jsonb and is unbounded, so a direct service role caller can store an
  object or 454 KB in one event row. The module always sends an array of one reason per entry.
* `runId` and `userId` are checked for a non empty string only, so a malformed pair becomes a
  PostgREST cast error rather than a module error. The cause is scrubbed, and the shipped callers pass
  database uuids.
