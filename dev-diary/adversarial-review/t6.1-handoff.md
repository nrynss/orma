# T6.1 handoff: Today

Implementation role. The work landed in `512b472`. Round 1 remediation changed the parts marked below.

## What exists now

`/app` is Today, rendered in the browser. It reads PostgREST under RLS through `ORMA_API_URL`, with the publishable key and the user JWT. It never writes.

Today has four states, chosen from `call_runs` rows.

- **Live.** A run in `claimed`, `dispatched` or `awaiting_result` shows Calling now, with steps from `claimed_at`, `dispatched_at` and `poll_after`. The page reloads its rows every 15 seconds while that state lasts. The first step reads "Picked up", as TodayLive does.
- **On today's call.** The live state lists items in the order of `call_runs.briefing.open_items`, with counts and ages from rows. A run with no briefing yet falls back to "Open · N" and says the order is still to come.
- **First run.** An account with no run ever placed or attempted shows Welcome. Scheduled and canceled runs do not count as calls. The first call time comes from the next scheduled run. Without one, it comes from the next active slot in the profile's zone.
- **Normal.** It shows the next call, the last call and the open items.
- **Error.** A failed read shows the message instead of blank panels.

Every time and date renders in `profiles.timezone`. The browser's zone plays no part.

Today never promises a call the dispatcher refuses. `callBlock` mirrors `dispatchOne` in `calle.ts`, in the same order. It checks for a confirmed number, then a live `outbound_calls` consent, then the run's own slot. A blocked account sees why, and a link to Settings, instead of a time.

The next call is the earliest `scheduled` run after now. Canceled, terminal, live and past runs never qualify. "Cancel this call" and "Change time" link to `/app/settings`. Nothing writes `call_runs`.

The last call is the latest terminal run that is not canceled. Its lines come from rows on that run.

- **Committed** reads `commitments` with its `evidence_offset_seconds`.
- **Retired** needs an entry in that run's `results.structured.retired_items` and a mention on the run at the same item and offset. Ingest writes both in one transaction. A later retire on the web, by MCP or on Telegram writes neither, so it never shows here.
- **Captured** reads a mention on a `call` item created after the run started.
- Ingest writes one mention per commitment. The summary skips that mention, so nothing appears twice.
- The mention count equals the `item_mentions` rows on the run.
- Duration appears only when `transcripts.raw` carries CALL-E's `started_at` and `completed_at`. The seed carries neither, so no duration shows.
- Offsets and "Read the transcript" link to `/app/history?run=<id>&t=<seconds>`, ready for T6.3.

Open items show a mention count from `item_mentions` rows and an age from `since_date`, or else `created_at`. Both are read in the profile's zone.

`/app/+layout.svelte` carries the app navigation on every `/app/*` page. Desktop shows the sidebar from DeskToday. Phone shows the header row and underline nav from Main. The current page carries `aria-current="page"`. Onboarding keeps the simpler wordmark shell from Onboarding.dc.html. The root shell bar hides inside `/app`. Outside `/app`, signed in, it links to Today instead of Settings.

`postAuthPath(true)` returns `/app`. Onboarding submit goes to `/app`. Login, the magic link callback and the hook all use `postAuthPath`, so all three now land on Today.

## The Today check

`src/lib/today/check.ts` sets the process zone to `America/Los_Angeles` before it runs. It pins these claims.

1. A run at 02:30 UTC renders "Today, 08:00" in Asia/Kolkata and "Today, 19:30" in the process zone. The check fails if they match, or if the render follows `Date#getHours`.
2. The next run skips an earlier canceled, completed, failed, claimed and past run. It picks the earliest future `scheduled` one.
3. First run is true for no runs and for scheduled plus canceled. It is false for completed, failed and awaiting_result. A canceled run that ends after a real call is never the last call.
4. Each mention count equals the rows given for that item. An item with no rows shows zero.
5. Age reads local days in the profile's zone, for both the row and now. The added label and the Today and Tomorrow labels count local days too. Each has a case where a UTC reading differs.
6. The last call counts committed, retired and captured from rows on that run only. A commitment on a captured item counts as one capture. An item retired after the call never reads as retired on it.
7. Slot fallback skips weekend days, ignores inactive slots and handles New York daylight time. A 06:30 slot on the spring-forward day lands at 10:30 UTC, which a single conversion pass misses.
8. Live steps and poll clocks render in the profile's zone.
9. The nav marks Today only on `/app`, and History on its subpaths.
10. On today's call follows the briefing order. No briefing falls back to the open list.
11. No number, an unconfirmed number, no live consent, a missing slot and a vanished slot each block the call.

## How a reviewer runs it

From the repository root:

```sh
scripts/p6-local-stack.sh up
cd web && env $(../scripts/p6-local-stack.sh env) npm run dev -- --port 5199
```

`up` refuses to start if its workdir or containers already exist, or if any port from 58320 to 58329 is taken. It prints no keys. `env` prints two names for the dev server: `PUBLIC_ORMA_API_URL` and the local demo `PUBLIC_SUPABASE_ANON_KEY`.

Use `env $(...)` exactly as written. Putting the line into a variable first breaks under zsh, because zsh does not split `$VAR`. The URL then swallows the whole line and every route answers 500 with "Invalid supabaseUrl".

The accounts all use the password `local-dev-password`.

| Account | Profile zone | What Today should show |
|---|---|---|
| `local@example.com` | Asia/Kolkata | The T1.6 seed. A harness `scheduled` run at the next 08:00 local, an earlier canceled run, and the seed's completed call. |
| `firstrun@example.com` | America/New_York | A profile, a slot and two Telegram items. No runs. |
| `live@example.com` | Europe/London | One run in `awaiting_result`, with a briefing from `assemble_briefing`. |

Login offers only magic link and Telegram, and neither works locally. Sign in from the browser console on any dev page instead. This uses the app's own client, so it writes the real cookie.

```js
const m = await import('/src/lib/supabase.ts')
await m.getSupabase().auth.signInWithPassword({ email: 'local@example.com', password: 'local-dev-password' })
```

Then open `/login`. It should redirect to `/app`. The cookie is named `sb-127-auth-token`, because supabase-js derives it from the API host `127.0.0.1`, not the page host.

Read SQL with `scripts/p6-local-stack.sh psql`, or with `docker exec -i supabase_db_orma-p6-local psql -U postgres`. Finish with `scripts/p6-local-stack.sh down`, then confirm `docker ps -a | grep orma-p6-local` prints nothing.

## Surprises

- `supabase start` ends with a status block that prints the local secret key and service role JWT. They are the CLI's fixed local demo values. The script filters that output anyway, so no key text reaches a log.
- The repo `config.toml` enables Resend SMTP with `env(RESEND_API_KEY)`. The scratch config drops that block and every `[functions.*]` block. It appends its own ports and disables studio, analytics, realtime, pooler and edge runtime. Storage stays on, because a migration creates a bucket.
- svelte-check type-checks the node check scripts but has no Node types. Both checks therefore reach `process` and `node:fs` through loosely typed handles instead of plain imports.
- The seed's completed run has no call duration. Neither does any CALL-E fixture field other than `started_at` and `completed_at` in the raw run. Today omits duration rather than inventing one from transcript offsets.
- `pkill -f "<pattern>"` inside a tool shell matches the shell's own command line and kills it. Use a bracketed pattern such as `'[v]ite dev'`.

- Open items sort by mention count, then age. The design artboard's order is illustrative and names no rule.
