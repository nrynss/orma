## Validation rules added in `ingest.ts`

Each rule mirrors a cast or raise in `ingest_call_result`. Rules 1 to 6 route to `valid=false`.

1. `captured_items[].text` must be non-blank after trimming. The SQL raises on a space-only or empty text.
2. `captured_items[].text` and `slot_change_time` must hold no U+0000 and no unpaired surrogate. jsonb refuses both, so PostgREST fails the whole call.
3. Every `evidence_offset_seconds` must lie in the int4 range. The SQL casts with `::integer`, which fails on `2147483648` or `1e21`.
4. `retired_items[].item_id` and `commitments[].item_id` must be canonical UUIDs. The SQL casts with `::uuid`.
5. `commitments[].due` must be an ISO 8601 date or date-time with a real calendar day. Hours run to 23, minutes and seconds to 59. Up to six fraction digits are allowed. A zone offset may reach 15:59. The year must be 0001 or later. The SQL casts with `::timestamptz`.
6. Every retired or committed item id must name an item this user owns. The SQL raises otherwise.
7. `raw.completed_at` is forwarded only when it passes rule 5, or else as null. The SQL casts it, and a null falls back to `now()`. This rule leaves `valid` unchanged.

Rules 4 and 5 are stricter than PostgreSQL. They refuse braced UUIDs and words like `tomorrow`. That is deliberate, since a stricter gate cannot poison the RPC.

The live tables have no check or unique constraint beyond primary keys and `idempotency_key`. `mood` has no constraint and the parser already limits it to an enum. So the rules above cover the whole class for the structured result.

## Residual risk not closed

* A U+0000 or lone surrogate in the transcript turns or the raw payload still fails the RPC. That data is not the result, so no `valid=false` path can absorb it.
* Two concurrent `already_ingested` retries can each find no `ingested` row and both write one. No unique constraint on `call_events` prevents it.
* An item deleted between the ownership read and the RPC makes that ingest raise. The next retry's read rejects the result, so the run recovers on retry.
* A non-UUID run or user id still fails at the RPC, now with a named cause. A pre-flight UUID check broke the `calle.ts` tests, which pass `run-1`. So the check was withdrawn.
* The port probe and `supabase start` leave a short race window with another process.
