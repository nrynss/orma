# T10.3 handoff: Confirmation UI

## What landed

The shared confirmation component serves onboarding and Settings. It starts the confirmation call, verifies a code, reports refusal and expiry, and updates the blocked call state without a reload.

Onboarding saves an unconfirmed number first. A person can verify immediately or skip to Today, where daily calls stay blocked. Changing a Settings number requires confirmation again.

## Safety and validation

The browser never writes `phone_confirmed_at`. Verification is form-free, so a code submission cannot submit the host onboarding or Settings form.

Round 2 approved with zero findings after the nested-form remediation. The boundary pin, `npm run check`, and `npm run build` passed.
