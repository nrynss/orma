# T2.8 contract change

T2.8 must decide dry mode before anything that can dial a phone. The task's
`owns` line named `_shared/dispatch-mode.ts` and `_shared/calle.ts`, which is
where the decision has to be made. Three seams had to move for it to be made
there and nowhere else.

The line this task must never cross is the same one the whole product defends.
A due run that places a real call because a setting was not read is a cost and
an embarrassment at once. So the dry decision sits ahead of the only outbound
operation this task can reach, and the module that makes it holds no URL, no
key and no fetch.

| Where | What | Pin | Mutation |
| --- | --- | --- | --- |
| `_shared/calle.ts` `ClaimedRun`, `tick/index.ts` `ClaimedTickRun` | Widen both shapes with `dry_run: boolean`, so the per-run decision reaches `dispatchClaimedRun` before any outbound-capable operation. | `public.claim_due_call_runs` returns `setof public.call_runs` with `returning call_run.*`, so the column already arrives in the claim response. The live dry-run proof claims a scheduled run through the real RPC and reads `call_runs.dry_run` back as false on a run that never dialled. | Removing the field leaves the dispatcher unable to see `call_runs.dry_run`. A run flagged dry in the database then places a real call, which is the one failure this product cannot survive. |
| `_shared/dispatch-mode.ts` fixture constants | Embed the recorded `call-completed.json` and `call-failed.json` payloads in the module instead of reading `testdata/` at runtime. | A deployed Edge Function bundles only its own directory, so `fixtures.ts`'s `Deno.readTextFile` of `../../../testdata/` cannot resolve in production. An inline test in `dispatch-mode.ts` re-reads both committed files and compares them to the embedded constants, so the two cannot drift without a failure. | Reading `testdata/` at runtime makes dry mode work in tests and fail on the deployed function, which is the only place a demo runs. Leaving the copies unpinned lets the recorded extraction change under a rehearsal. |
| `_shared/dispatch-mode.ts` `executeDryRun` signature | Take `userId` and an injected `ingest` dependency, and return the ingestion summary. | T2.8's done condition requires a full dry run to produce items and mentions. Ingestion is T2.7's, and a task-level `requires` binds, so T2.8 depends on it. The dependency is injected, so no fetch and no CALL-E address enters `dispatch-mode.ts`. | Without ingestion a dry run stops at a terminal state with no items, which fails the task's own done condition. Calling ingestion directly from this module would put a fetch inside the one module that must stay unable to dial. |

## Ordering, applied to all three terminal writers

`executeDryRun` writes the terminal `call_runs` row first, then records
`dispatched`, then ingests, then records `finalised`. This is review finding
T2.8-H1. The same ordering has to hold in `poll.ts`'s terminal write and in
`calle-webhook`'s `terminaliseFromRefetch`, because all three move a run to a
terminal state outside `calle.ts`. The dry-run proof pins the order by failing
the run write and asserting that no `dispatched` row is recorded.
