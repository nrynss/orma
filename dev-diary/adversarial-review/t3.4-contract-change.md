# T3.4 contract change request

T3.4 owns only `supabase/functions/_shared/deliver-telegram.ts`.
Helpers and REST adapters live there. Deno tests live in
`deliver-telegram_tests.ts` beside it because MCP push size forced a split.

T7.4 and T7.3 call the exported API. This task does not edit those files.
T3.1 does not need to call delivery. Receipts are outbound from analysis and ingestion.

## Documented choices

Disabled or unlinked profiles skip entirely. No Telegram call.
No `deliveries` row. Task done-when says the user gets nothing.
Silence beats an audit row for a channel the user turned off.

Post-call callers pass `capturedTexts` and `retiredTexts` as strings.
`retired_items` in structured results carry only `item_id`.
T7.4 resolves ids to item text before calling this seam.
T7.4 also passes `committedTexts`, resolved from `structured.commitments`.
The formatter renders a `Committed` section only when the list is non empty.
The orchestrator added this line to close the gap T7.4 round 1 named by file.

Pattern callers pass validated prose. This seam does not rewrite it.
CTA enforcement applies to post-call formatting, not T7.2 prose.
