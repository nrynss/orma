## The round-2 design choices, judged

**A failed re-fetch past the window gives up.** This is not a defect against the specification, for three reasons. First, the premise that nothing can correct it is false. The ingest RPC writes `state` and `disposition` from the re-fetched payload, not from the run. Second, T2.7a re-fetches every terminal run with a null `completed_at` and retries a failing re-fetch. So the state self-corrects once CALL-E answers again. Third, the webhook cannot correct it, but it does not need to. The residue that survives is the third finding. The remediation understates the trigger. A single failed re-fetch on the first overdue pass is enough, not an outage longer than the window. Pin RO shows the same end state from a clean race.

**Redelivery detection on a 409.** A 409 correctly marks a redelivery. The attribution that follows is unsound. See the first two findings.

**The remediator's open item.** This is a real defect, not a residual. Pin F1b measures it, and pin F1c shows a race reaches the same result with no write failure.

**Success counting.** `countSucceeded` counts a pass that resolved. A rescheduled pass after a failed re-fetch counts, which is fair, because it wrote its row. A pass whose PATCH landed and whose insert failed counts as not polled. That is the second finding's root, not a separate defect.

## Requirement check

1. **Bounded window.** The poll's window holds for runs with and without `dispatched_at` (pins M and A). The run's life is not bounded, because T2.7a retries a pending re-fetch forever. That belongs to T2.7a.
2. **One pass per tick.** `tick()` calls `pollDue` once per due run, and `pollRun` makes at most one re-fetch (pins A and M counted one).
3. **Isolation.** Poll and finalise each catch per run. The real tick answered 200 beside a throwing finaliser (pin T).
4. **Exactly one winner.** Twelve raced rounds, six of them overdue, each ended with one state writer (pins R and RO).
5. **State only from the re-fetch.** Every state write followed a re-fetch in every pin. A give-up after a failed re-fetch writes `failed` without one, and ingestion later overwrites it (pin F2).
6. **Truthful timeline rows.** This does not hold. Two writers can each claim one transition (pins F1a, F1b, F1c).

## Residual risk

- **Live timing proof.** The T2.5 done condition needs a real CALL-E key, which this round did not use. A live call is evidence, not a gate.
- **Two terminal events per call.** Pin F1a assumes CALL-E can send two terminal event ids for one call. The contract lists `call.completed` and `call.result_validation_failed`. Nobody has observed whether both fire together.
- **Overlapping ticks.** `duePolls` takes no claim. Two overlapping ticks can double-poll a pending run. The guard still yields one terminal winner. I did not pin this.
- **Timeout leaves `poll_after` set.** Pin F2 read `poll_after` non-null on a completed run. `duePolls` filters on state, so nothing polls it again.
- **Webhook transition omits provider detail.** The webhook writes only `state` and `poll_after`. T2.7a must re-fetch before ingestion.
- **`refetched` keeps `state` beside `outcome`.** T2.9 must read `outcome` before it trusts that state.
