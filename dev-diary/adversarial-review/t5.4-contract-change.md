# T5.4 contract change

The original `owns` line named only `web/src/routes/app/onboarding/`. A new
account that already has a session would skip this flow, because T5.3 sends
signed-in users to `/app/settings`.

| Where | What | Pin | Mutation |
|---|---|---|---|
| `web/src/hooks.server.ts` | T5.3 sends every signed-in `/login` visit to `/app/settings`. If the session has no `public.profiles` row, send it to `/app/onboarding` instead. Also send `/app` and `/app/*` except onboarding there. | A signed-in user with no profile who opens Settings or `/login` lands on onboarding. | Without the gate, a new account hits Settings mint, which fails because `telegram_link_tokens.user_id` references profiles. |
| `web/src/routes/+layout.server.ts` | Expose whether a profile exists so the tree can render the gate without a second guess. | Server load for a fresh account has no profile. | The hook and the pages disagree about where to send the user. |
| `web/src/routes/login/` | After a successful session, send a user with no profile to `/app/onboarding` rather than Settings. | Magic-link callback for a fresh account lands on onboarding. | The callback keeps sending new users to Settings, so the first-run path never runs. |

Do not rewrite the login form, the Telegram widget, or cookie handling. This
task takes the missing-profile branch only. Do not put the service role in
`web/`. Profile lookup uses the user JWT under RLS.
