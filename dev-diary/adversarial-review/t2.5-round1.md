### Suggested shape for the tick isolation

```ts
  const terminal = await terminalRuns(deps)
  await Promise.all(terminal.map(async (run) => {
    try {
      await deps.finalise(run)
    } catch (error) {
      console.error(
        `finalise failed for run ${run.id}`,
        error instanceof Error ? error.message : "unknown error",
      )
    }
  }))
```

## Residual risk I could not close

- The real CALL-E re-fetch payload is unpinned. The stack serves fixtures only, so `fetchCall` and `parseAuthoritativeCall` are proven against the committed shape, not against a live `GET /v1/calls/{id}`. The T2.5 done condition, one live call through polling alone, stays open and needs a real key.
- The ten-second reschedule is bounded below by the one-minute cron cadence. Real passes land about sixty seconds apart, so the effective window stretches to roughly fifteen passes, not ninety. Harmless, but the requirement's ten seconds only ever appears inside `poll_after` values.
- A persistent failure of the shared `duePolls` or `terminalRuns` read aborts the whole tick before any poll runs. That path predates T2.5 and my harness could only poison per-run reads.
- If the webhook somehow delivers before dispatch's own transition PATCH, the run sits in `claimed`, the webhook's guarded write matches zero rows, and the poll resolves it sixty seconds later. Self-healing, out of scope, no state corruption.
