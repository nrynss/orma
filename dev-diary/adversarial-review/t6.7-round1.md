## Scope and evidence

I read `AGENTS.md`, the T6.7 specification, the T1.2 RLS migration, the core
schema, the tick claim function, the audio object path, and both generated type
files. I inspected the migration and types directly. I did not modify them.

The migration uses `security definer` and an empty search path. Both functions
derive the user from `auth.uid()` and accept no user identifier. Both revoke
`public` and `anon`, then grant execution to `authenticated`.

`cancel_call_run` selects the caller's row with `FOR UPDATE`, checks `scheduled`,
sets state and disposition to `canceled`, marks it non-billable, and inserts one
`canceled` event. The tick claims only scheduled rows with `FOR UPDATE SKIP LOCKED`,
so the lock winner prevents a cancelled run from dispatching.

`delete_my_account` deletes only `item-audio` objects whose first path segment is
the caller UUID. The voice path uses that exact directory shape. Deleting the auth
row then relies on the existing profile cascades. The generated browser and Edge
Function types contain matching RPC signatures and return types.

`npm run check` in `web/` passed with zero Svelte diagnostics. No T6.2 integration
conflict was found. The T6.2 page does not call these RPCs, which is correct because
settings owns cancellation and deletion in T6.5.
