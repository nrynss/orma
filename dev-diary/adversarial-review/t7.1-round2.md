## False positives I rejected

**Spec section 10 names streaks and the facts object has no streak field.** The T7.1 block in
`PHASE-7-analysis.md` is the binding work breakdown for this task and names no streak. The word
appears once in the repository, undefined, with no consumer reading such a field. observed_days and
sufficient_history pin the consistency claim the contract states explicitly. A field requirement
invented from one summary word would be authorship, not review.

**The header comment at `test-facts.sh` lines 69 to 71 says in-window timestamps sit at
01:00+05:30 while several sit at 06:00 or 06:30.** Read as a claim about the load-bearing rows the
comment is exact, and the per-fixture comments at lines 102 to 104 and 158 to 162 state the
invariant precisely. Mutation run A proves the proof works as built. Comment polish only.

**The retired-item created_at cast at `facts.sql` line 62 is unpinned on its own.** days_open
subtracts two cast dates, so a paired shift cancels. Line 68 pins the cast set through window
membership, and mutation run A fails on it. The brief requires the full drop to fail, and it does.

**The residue guard runs only on the success path.** A failed run cleans up through the same exit
trap with no second guard. The primary failure already exits nonzero, so residue there is
speculative, and a second exit code in the trap risks masking the first failure.

**Round 1 rejections stand.** The canceled-only day 09-04 counts as observed because the contract
sets no rule and SQL and fixture agree. answered_runs filters disposition only, as the contract
scopes cancellation to slot rates. A canceled run with a non-null mood would count in the mood
distribution, with no fixture row and no contract breach. The `where cr.slot_id is not null` clause
stays redundant beside the inner join. Random port collisions follow the approved T2.2 harness
scheme. Explicit fixture ids match the established shape.
