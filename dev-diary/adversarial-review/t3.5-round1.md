## Independent checks

`deno` was not on PATH. Deno 2.9.6 was installed only for this review.

`deno test --allow-read supabase/functions/telegram/link.ts` reported 7 passed, 0 failed.

A fresh mint then `completeLink` on the memory store set `profiles.telegram_chat_id` to the start chat. The store had no row keyed by the raw token.

A second `completeLink` with the same token returned `replay`. The original chat id stayed on the profile. The second chat id did not resolve.

`completeLink` at `now + LINK_TOKEN_TTL_MS` returned `expired`. `telegramChatId` stayed null. `consumedAt` stayed null.

`completeLink` at `now + LINK_TOKEN_TTL_MS + 1` also returned `expired`. That matches the shipped expiry test.

`tokenFromStartText("/start")` returned null. `completeLink` then returned `missing`. `messageForLinkOutcome` equalled `START_LINK_PROMPT`.

`encodeLinkToken` of 32 random bytes produced a 43-character payload. `hashLinkToken` produced 64 lowercase hex characters. `telegramStartDeepLink("@orma_tele_bot", token)` equalled `https://t.me/orma_tele_bot?start=` plus that token.

The shipped REST test posted `token_hash` to `https://orma-api.nryn.dev/rest/v1/telegram_link_tokens`. The body did not contain the raw token. The URL did not contain `supabase.co`.

An independent REST double for `completeLink` sent PATCH with `consumed_at=is.null` on that same host.

`git show --name-only 6c34368` listed only `supabase/functions/telegram/link.ts` and `dev-diary/adversarial-review/t3.5-contract-change.md`. T3.1 `index.ts` was not in the commit.

`test -f supabase/migrations/*telegram_link*` exited 1. Generated types have no `telegram_link_tokens` table.

## Accepted for this round

The contract note is honest. T3.5 cannot add `telegram_link_tokens`, wire T3.1 `/start`, or mint from Settings. Those seams sit outside `owns`.

Done-when bind, replay, expiry, and unlink are met on the memory store. They are not met on a live Start press until T3.1 calls `completeLink`. That gap is the named contract change, not a silent owns breach.

A taken chat consumes the token. Spec says a token is consumed on first use. The retry then returns `replay`. That is not recorded as a finding.

`profiles` RLS still lets an owner PATCH `telegram_chat_id` without a token. T1.2 owns that policy. T3.5 cannot close it.

Tests live in `link.ts` because that is the T3.5 `owns` seam.

T3.5 status remains `claimed:orma`. This review does not mark the task done.
