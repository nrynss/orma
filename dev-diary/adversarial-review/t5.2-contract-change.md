# T5.2 contract change

The original `owns` line named only `supabase/functions/auth-telegram/index.ts`.
The browser posts the Login Widget payload with no session, so the gateway JWT
check has to be off for this function. That flag lives in `config.toml`.

| Where | What | Pin | Mutation |
|---|---|---|---|
| `supabase/config.toml` `[functions.auth-telegram]` | Add `verify_jwt = false` for this function only. The handler still verifies the widget HMAC and refuses a stale payload. | A POST with no Authorization header reaches the handler. A missing or wrong `hash` still returns 401. | Leaving the gateway check on makes every unsigned widget POST fail before HMAC runs, so Telegram login cannot mint a session. |

Do not edit `[auth]`. T5.1 owns that block. Do not edit `[functions.telegram]`.
T3.1 owns that block. No proxy path is required. The login page posts to
`${ORMA_API_URL}/functions/v1/auth-telegram`.
