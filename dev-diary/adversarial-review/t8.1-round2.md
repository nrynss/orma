## Notes, not findings

- `--remove` deletes a non-seed mention that sits on a seeded item (evidence 17). The item goes, and the FK cascades its mentions regardless of the script. The task says remove deletes seeded rows and nothing else. A mention of a seeded item cannot outlive that item, so I accept this. Non-seed items and their rows survive.
- `--remove` against a non-local URL still needs no confirmation flag, as round 1 noted.
- Seeded run ids do not depend on the demo date, so a rerun with a new date updates in place (evidence 16). A rerun can land a seeded run on a date where the account already holds a real run for the same part of day. No unique constraint stops that, and slot answer rates would count both. The operator should pick a demo date with that in mind.
- Patterns in production depend on when `analysis` runs. The Monday cron window must contain the three seeded dates, or the operator must invoke `analysis` inside that week. The seed places the runs correctly for a demo date, and the timing is operational.
- The remediation file has one row per finding but no ID column. It carries the severity inside `where`. That is not a defect in the subject.
- Comments in `scripts/seed.ts` contain no semicolons, no em dashes and no sentence over 30 words by my scan.
- No secret was printed. I used no `orma-api.nryn.dev` request, no linked project and no production write. The local stack is down.
