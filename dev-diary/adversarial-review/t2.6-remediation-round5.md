## Design decision, a re-fetch without a usable status

A re-fetch that carries no usable status is not actionable, so the receiver
treats it like an ownership mismatch. The receiver marks the event `ignored`
and returns 200. It writes no timeline row. This keeps a body value out of the
run's authoritative state. The pin
`ignores a re-fetch that carries no usable status and writes no timeline row`
asserts the 200, the `ignored` state, and that `call_events` is never called.

## Fixture and mock updates

Every mock that returns a re-fetch response now carries `status`. The old pin
at `index.ts:416` now drives a body of `call.failed` while the re-fetch reports
`status` `completed`. The pin asserts both rows carry `event_type` `call.failed`
and that only the `refetched` row carries `state` `completed`. It also asserts
that no row carries `state` `call.failed`.
