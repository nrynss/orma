## F1: the label fits because the weight cue is gone

The clipping has one cause and the fix removes it rather than shaving pixels until it just fits.
At 320 the cells are 53.33 wide, the tab keeps 1 pixel of side padding, and the label box is
therefore 51.33. The semibold `Timeline` wants 51.52 and rounds up to a 52 pixel scroll width
inside a 51 pixel box. At the medium weight the same word wants 48.7.

I weighed the three options the round names and rejected two of them.

- **Tightening the 1 pixel padding or the tracking** buys about 1.3 pixels, which leaves no
  slack and puts the bar one font update away from clipping again at the same width. It also
  removes the label's only breathing room against the cell edge.
- **Reducing the label font size** shrinks all six labels to rescue one word, and it departs
  from the type scale the tokens fix for every other small string in the product.

Dropping the weight fixes the cause, costs nothing, and leaves 2.6 pixels of headroom at 320.
The widest label at the medium weight is 48.7, whether the page is Timeline or Patterns, so the
bar now fits every one of the six tabs with room to spare.

The current tab still needs to be unmistakable, and P9 requires more than colour alone. It
carries three marks: `aria-current="page"`, `color: var(--brand)`, and a 3 pixel brand rule above
its icon that spans the cell. The rule is a shape, it costs no layout width because it is
absolutely positioned, and it matches the underline `AppNav` already uses for the current link in
its phone row. The rule and the label measure 8.65 to 1 in light and 8.92 to 1 in dark against
the bar surface, well above the 3 to 1 floor for a non-text control.

Both themes hold. At 320 the rule reads `rgb(111, 43, 127)` light and `rgb(217, 166, 234)` dark,
`Timeline` renders whole in each, and exactly one tab in the bar carries the rule.

The desk frame is unchanged. At 1280 the bar is `display: none`, one nav renders, and the sidebar
keeps the `AppNav` cue it already had, which is a `--brand-soft` fill with the semibold weight.
I did not touch that file.

The label keeps `overflow: hidden` and `text-overflow: ellipsis` as a last resort. Reverting the
fix, by restoring the semibold weight and deleting the rule, puts a truncated `Timeli…` back on
the screen at 320.

## F2: the panel closes on a press outside it

`AccountMenu.svelte` now binds its wrapper and runs one effect on `open`:

```
$effect(() => {
	if (!open) return
	const onPointerDown = (event: PointerEvent) => {
		const target = event.target
		if (target instanceof Node && root?.contains(target)) return
		open = false
	}
	document.addEventListener('pointerdown', onPointerDown)
	return () => document.removeEventListener('pointerdown', onPointerDown)
})
```

The effect returns early while the panel is closed, so the listener exists only while the panel
is open. A press inside the block is ignored, which keeps the trigger's own toggle and the Sign
out action working. A press anywhere else closes the panel.

I chose `pointerdown` over `click` for two reasons. It fires for mouse and touch alike, and it
runs before the element under the press acts, which is the order a menu should close in.

The keyboard path is untouched. Escape still closes the panel from the existing
`<svelte:window onkeydown>` handler, and Enter on the trigger still opens it. The listener count
on `document` is the pin for the leak, and it returns to zero at every close:

| Step | `aria-expanded` | Panel rendered | `pointerdown` listeners on `document` |
|---|---|---|---|
| Closed | false | no | 0 |
| Opened by the trigger | true | yes | 1 |
| Press at (8, 120), outside the block | false | no | 0 |
| Still closed after settling | false | no | 0 |
| Reopened by the trigger | true | yes | 1 |
| Press inside the panel | true | yes | 1 |
| Closed by the trigger again | false | no | 0 |
| Enter on the focused trigger | true | yes | 1 |
| Escape | false | no | 0 |
| A tab click, which navigates | false | no | 0 |
| Navigating to `/app/onboarding`, which unmounts the block | no trigger | no | 0 |

The last two rows cover the two ways the component goes away. `afterNavigate` still closes the
panel, and the effect's cleanup removes the listener on unmount. Reverting the fix restores the
state the round measured: the panel stays open over the page after a press outside it.
